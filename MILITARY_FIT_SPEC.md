MILITARY FIT

COMPLETE MASTER DEVELOPMENT PROMPT

Personalised Military Calisthenics, Fitness Coaching & Body Transformation System

1. PROJECT VISION

Build a complete, modern, intelligent and mobile-first fitness application called MILITARY FIT.

MILITARY FIT is a personal fitness training and body-transformation platform designed to understand individual fitness goals, assess current ability, generate personalised training programmes, guide exercise sessions, recognise physical activity through a smartphone camera and measure genuine progress.

It should function like having a personal military-style fitness coach available on a smartphone.

The application must not assume that everybody wants to lose weight, build muscle or follow the same programme. It must first understand each user's personal objectives and then recommend an appropriate training journey.

The application should initially be optimised for personal use on an Android smartphone while using an architecture that can support multiple users in the future.

Core objectives

1. Understand what each user wants to achieve.
2. Assess their current fitness level and physical condition.
3. Establish measurable fitness goals.
4. Generate a personalised training programme.
5. Provide animated exercise demonstrations.
6. Use the phone camera to recognise genuine exercise activity.
7. Count repetitions automatically where supported.
8. Measure actual exercise time rather than screen-open time.
9. Track body measurements and fitness performance.
10. Provide nutrition and hydration guidance.
11. Adapt training based on real performance and recovery.
12. Generate weekly progress reports.
13. Help users remain consistent and motivated.

This must be a functional application, not a static prototype. All important features, buttons, navigation, calculations, camera operations, timers, data storage, reports and user interactions must work.

9. CAMERA-BASED EXERCISE RECOGNITION

This is a core feature of MILITARY FIT.

The smartphone camera should help determine whether the user is genuinely performing the prescribed exercise.

The application must not simply detect a person standing in front of the camera and count that as exercise.

It must analyse body positions and exercise-specific movements.

Recommended technology

Evaluate:

- MediaPipe Pose Landmarker.
- TensorFlow.js pose estimation.
- Other suitable on-device pose recognition solutions.

Choose the most appropriate technology based on accuracy, Android compatibility, performance, privacy and cost.

Prefer on-device processing wherever practical.

Camera setup

Before camera-assisted exercise:

1. Request camera permission.
2. Explain why camera access is required.
3. Show a live camera preview.
4. Give instructions on phone positioning.
5. Check body visibility.
6. Check whether required body landmarks are detected.
7. Guide the user to adjust their distance or camera angle.
8. Confirm when the system is ready.

Show a visible body-position guide.

Do not start repetition counting just because a body has been detected.

Exercise-specific recognition

Push-ups

- Track shoulders, elbows and wrists.
- Detect lowering and rising phases.
- Count only a valid complete cycle.

Squats

- Track hips, knees and ankles.
- Detect lowering and standing phases.
- Evaluate movement depth using suitable thresholds.
- Count only completed movements.

Lunges

- Track hips, knees and ankles.
- Detect a valid lunge.
- Track left and right legs separately.

Jumping jacks

- Detect arm and leg opening and closing.
- Count a complete cycle.

Mountain climbers

- Detect alternating knee movements.
- Avoid double counting.

Crunches

- Detect controlled torso movement.
- Count complete repetitions only.

Planks

- Recognise a valid static plank position.
- Monitor body alignment.
- Maintain the timer while the position remains valid.

Walking

- Detect continuous walking activity where the camera angle supports reliable recognition.

Live feedback

Display messages such as:

- Body detected.
- Move further back.
- Adjust your camera.
- Exercise position recognised.
- Movement detected.
- Rep counted.
- Keep your back straight.
- Lower your body further.
- Tracking lost.
- Return to the exercise position.

Use confidence thresholds.

If tracking confidence becomes too low, pause verification and notify the user.

Do not silently count repetitions or active time when the system cannot reliably recognise the exercise.

Camera limitations

Different exercises require different viewing angles.

Some require a side view, others a front view.

Implement the most reliable exercises first and expand after real-device testing.

Never claim that an exercise was camera-verified merely because a person was detected.

10. INTELLIGENT ACTIVITY-AWARE TIMER

This is a mandatory feature and one of the most important technical requirements.

The application must measure genuine exercise activity rather than the time the workout screen remains open.

It must distinguish between:

- Standing still.
- Preparing to exercise.
- Actually exercising.
- Taking a short pause.
- Taking a longer break.
- Completing a set.

Scenario A — User stands in front of the camera

The camera detects the user, but no exercise is being performed.

Expected result:

- Body detected.
- Exercise not started.
- Active timer remains at zero.
- No repetitions counted.

Scenario B — User starts exercising

The system detects valid exercise-specific movement.

Expected result:

- Exercise recognised.
- Active timer starts.
- Valid repetitions are counted.
- Progress is displayed.

Scenario C — User stops exercising

The user stands still.

Expected result:

- Inactivity detected.
- A short configurable grace period is allowed.
- Active timer pauses after the inactivity threshold.
- No additional repetitions are counted.

Scenario D — User resumes

Expected result:

- Valid movement recognised again.
- Active timer resumes.
- Previous repetitions are preserved.
- No timer reset occurs.

Scenario E — User completes a set

Expected result:

- Set timer stops.
- Verified repetitions and active time are saved.
- Rest timer starts.
- User can proceed to the next set.

Maintain three independent timers

1. Active Exercise Timer

Measures only recognised exercise activity or valid static holds.

2. Rest Timer

Measures breaks between sets and exercises.

3. Total Session Timer

Measures the complete workout duration, including exercise, rest and pauses.

Never combine these measurements.

Repetitive exercises

- Detect complete movement cycles.
- Accumulate active time during valid exercise activity.
- Allow brief natural pauses.
- Pause after the configured inactivity threshold.

Initially use approximately 2–3 seconds for repetitive movements, configurable for each exercise.

Static exercises

For planks and similar holds:

- Recognise a valid starting position.
- Start the timer when the position is correct.
- Continue timing while the position remains valid.
- Pause when the position is lost.
- Resume when the user returns to the correct position.

Do not treat all inactivity as stopping. A correctly maintained plank is an active exercise even though there is little movement.

Technical timer implementation

Use timestamp-based elapsed-time calculations rather than relying exclusively on one-second interval increments.

Account for:

- Browser throttling.
- Delayed rendering.
- Temporary interruptions.
- Camera tracking loss.
- Application backgrounding.
- Camera permission changes.

Maintain these workout states:

- "WAITING_FOR_USER"
- "BODY_DETECTED"
- "EXERCISE_READY"
- "EXERCISE_STARTED"
- "EXERCISING"
- "TEMPORARY_PAUSE"
- "RESTING"
- "SET_COMPLETED"
- "WORKOUT_COMPLETED"

Provide manual pause, resume and stop controls.

If the user leaves the application, locks the screen or loses camera access, stop claiming camera verification. Handle interruptions safely and accurately.

Example report

A 10-minute exercise session could show:

- Total session time: 10 minutes.
- Verified active exercise time: 6 minutes.
- Rest time: 3 minutes.
- Other pauses: 1 minute.

The application must not report all 10 minutes as actual exercise time.
